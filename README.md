# A Purple — Social Media Manager portfolio

A single-page portfolio site for a social media manager / strategist, styled with
**Tailwind CSS v4**. The markup, the styles and the behaviour now live in separate files,
so `index.html` stays short and readable instead of being one 95 KB blob.

The compiled stylesheet **is committed** (`assets/css/site.css`), which means:

- to **publish** the site you still just drag the folder somewhere — no build required;
- to **change the design** you edit `src/input.css` and run `npm run build`.

---

## 1. What is in this folder

| File / folder | What it is | Edit it? |
| --- | --- | --- |
| `index.html` | All the markup. No `<style>` block and no page script — just content and structure. | **Yes** — text, numbers, links, images |
| `src/input.css` | The Tailwind **source**: design tokens (`@theme`) plus every component class (`.card`, `.btn`, …). | **Yes** — colours, spacing, any styling |
| `assets/css/site.css` | The **compiled** stylesheet that `index.html` loads. Committed on purpose so deploys keep working. | **No** — regenerated by `npm run build` |
| `assets/js/main.js` | All page behaviour: mobile menu, scroll reveals, counters, form handling, back-to-top. | Only to change behaviour |
| `package.json` | Build scripts + the Tailwind dev-dependency. | Rarely |
| `package-lock.json` | Exact dependency versions npm recorded. | **No** |
| `.gitignore` | Keeps `node_modules/` out of git. | Rarely |
| `node_modules/` | The downloaded build tools. **Never upload this** — it is toolchain, not website. | **No** |
| `Moodboard/Portfolio inspiration.jpg` | The design reference the site was built from. Not part of the site. | No |
| `README.md` | This document. | No |
| `images/` | Your own photos. Currently holds `hero.jpg` (see section 4). | Yes |

### Rule of thumb

| I want to change… | Edit… | Then… |
| --- | --- | --- |
| Wording, numbers, links | `index.html` | save — done |
| Colours, fonts, spacing, shadows | `src/input.css` | save, then `npm run build` |
| Behaviour (menu, counters, form) | `assets/js/main.js` | save — done |
| Something in `assets/css/site.css` | **don't.** It is generated; your edits get overwritten on the next build. | edit `src/input.css` instead |

### Preview it locally

The quickest look needs no tooling at all, because the compiled CSS is already committed:

```powershell
start index.html                     # double-clicking the file works too
```

To preview it the way a visitor will (real URLs, a form that can actually POST):

```powershell
npm run serve                        # python -m http.server 8000  ->  http://localhost:8000
```

### Working on the design (the build step)

Only needed when you change `src/input.css`:

```powershell
npm install        # once - downloads Tailwind into node_modules/
npm run build      # compiles src/input.css -> assets/css/site.css (minified)
npm run dev        # same, but rebuilds automatically every time you save
```

`npm run build` completes in well under a second, so there is no reason to fear it.

> **On Windows PowerShell**, if `npm` reports *"npm.ps1 cannot be loaded because running
> scripts is disabled"*, call `npm.cmd` instead (e.g. `npm.cmd run build`). That is a
> Windows execution-policy setting, not a problem with this project.

### Repo state

`git` is **not** initialised here yet. There is no history to preserve, so you are free to
start a fresh repository (section 6, option B). `.gitignore` is already in place, so
`node_modules/` will never be committed.

## 5. Making the enquiry form actually send

Out of the box the form is a **working demo**: it validates the name, email and message in the
browser, shows inline error messages, and on a valid submission shows
"…this form is not connected to an inbox yet, so please email me directly" instead of a broken
page. Nothing is sent and no address is exposed.

To make it deliver to your inbox:

**Option A — Formspree (free tier, works anywhere)**

1. Sign up at `formspree.io` and create a new form.
2. Set the delivery email (where enquiries land) and copy the endpoint it gives you, e.g.
   `https://formspree.io/f/abcdwxyz`.
3. Paste it into the `action=""` attribute of the `<form id="contact-form">` tag in `index.html`,
   replacing the whole `[PLACEHOLDER: …]` value. That is the only change needed — the script
   picks it up automatically.
4. Deploy, then submit the live form once to confirm it arrives.
5. Add your deployed domain under the form's **Settings → Domains** so only your own site can
   post to it.

The form already sends two Formspree extras: a hidden `_subject` ("New portfolio enquiry") so the
email has a readable title, and a hidden `_gotcha` honeypot field that filters out bots.

Submission happens over `fetch`, so the visitor stays on your page and the reply appears inline in
`#form-status` — no redirect to Formspree's thank-you page. If the request fails, an error message
asks them to email you directly. With JavaScript disabled the browser falls back to a normal
`POST` to the same endpoint.

**Option B — Netlify Forms (only if you deploy on Netlify)**

Add `netlify` to the `<form>` tag plus a hidden
`<input type="hidden" name="form-name" value="contact">` field, and Netlify captures submissions
in its own dashboard. Formspree is simpler if you are unsure.

The script auto-detects the difference (`assets/js/main.js`, section 7 — the `endpointReady` check):
as long as `action` starts with `http` and no longer contains `[PLACEHOLDER`, it posts to Formspree.

## 6. Publishing it for free

**First, make a clean copy.** `node_modules/` must never be uploaded — it is the build toolchain,
not the website, and it is tens of megabytes. Run the helper:

```powershell
npm run pack        # copies index.html + assets/ (+ images/) into dist/
```

…then drag the `dist/` folder. If you would rather not use a helper script, everything the browser
actually needs is: `index.html`, `assets/` and `images/` (once you have it).

### Option A — Netlify drag & drop (fastest, about 2 minutes)

1. Sign up / log in at `netlify.com` (the free tier is plenty).
2. Go to `app.netlify.com/drop`.
3. Drag the **`dist/`** folder (or your hand-made clean folder) onto the page.
4. It publishes immediately at a random address like `https://brave-otter-1a2b3c.netlify.app`.
5. **Site configuration → Change site name** → e.g. `apurple` → `https://apurple.netlify.app`.
6. **Domain management → Add a domain** if you own one; HTTPS is issued automatically
   (Let's Encrypt) and is free.
7. To update later: re-run `npm run pack` and drag `dist/` onto the same site's Deploys page.

### Option B — GitHub Pages (free, versioned)

```powershell
cd C:\Users\JESSICA\Desktop\portfolio
git init -b main
git add .
git commit -m "A Purple portfolio"
# Create an EMPTY repository on github.com first, e.g. "apurple-portfolio".
# Do NOT add a README or .gitignore when creating it.
git remote add origin https://github.com/YOUR-USERNAME/apurple-portfolio.git
git push -u origin main
```

`git add .` is safe here: `.gitignore` already excludes `node_modules/` and `dist/`. Because
`assets/css/site.css` is committed, GitHub Pages serves perfectly styled pages with **no build
step at all**.

Then in the repository: **Settings → Pages → Source: Deploy from a branch → Branch: `main`,
folder `/ (root)` → Save**. About a minute later your site is live at:

```
https://YOUR-USERNAME.github.io/apurple-portfolio/
```

Custom domain: add a file named `CNAME` (no extension) next to `index.html` containing only your
domain, then add the DNS records GitHub shows you in Settings → Pages.

### Option C — Cloudflare Pages or Vercel

Both have free tiers and support drag-and-drop or "import from Git". If you connect the Git
repository, set the **build command** to `npm run build` and the **output directory** to `/`.
The compiled CSS is already committed, so the build is optional — it just guarantees the CSS is
in sync with `src/input.css`.

### 7.3 Two things worth knowing before you edit

**N-column grids use `grid-cols-[repeat(N,1fr)]`, not `grid-cols-N`.**
Tailwind's `grid-cols-N` emits `minmax(0,1fr)`, whereas the original design used bare `1fr`
(`minmax(auto,1fr)`), which lets a column widen to fit its content. The two distribute space
differently — switching the results row to `grid-cols-4` wrapped one stat label and made the page
20px taller. If you rewrite one of these, run `npm run build` and eyeball that part of the page.

**The white-card-inside-a-dark-band gotcha.**
These rules near the top of the components layer paint headings and bold text **white** inside the
two dark bands (`#results` and `#contact`):

```css
.is-dark h1,.is-dark h2,.is-dark h3,.is-dark h4,
.is-dark strong,.is-dark b{ @apply text-white }
```

So any *white* panel placed inside a dark band has to re-assert its own text colours — which is
exactly why the enquiry form carries these two lines (line 637), placed **after** the block above:

```css
.is-dark .form h3{ color:var(--color-plum) }
.is-dark .form .form__hint{ color:var(--color-muted) }
```

If you add a white card into a dark section and its heading seems to vanish, this is the reason.

### 7.4 Motion and accessibility

Visitors who have "reduce motion" enabled get a still page: the fade-up reveals, the animated
counters and the smooth scrolling all switch themselves off. That is handled by
`@media (prefers-reduced-motion:reduce)` in `src/input.css` (line 751) together with the
`reduceMotion` check at the top of `assets/js/main.js` (line 10).

With JavaScript disabled, the `<noscript>` style block at `index.html` line 101 reveals every
animated section, so nothing is left invisible.

## 8. How this refactor was verified

The split was checked mechanically rather than by eye, because "it looks about right" is not good
enough when CSS is being rewritten wholesale.

- **Computed-style regression diff.** The original single-file page and the new Tailwind build were
  both loaded in headless Chrome and `getComputedStyle()` was compared across **108 selectors ×
  53 properties** at **390px, 900px and 1440px**. Document height matched exactly at all three
  (`16693 / 11436 / 10272` px), which means nothing reflowed or re-wrapped.
- The differences that remain are provably invisible: Tailwind's Preflight sets
  `border-style: solid` on zero-width borders, composes `box-shadow` into five layers with the
  first four fully transparent, and writes `border-radius: calc(infinity * 1px)` where the original
  used `50%` on perfect squares. `start` vs `flex-start` is a CSS alias for the same behaviour.
- **No horizontal overflow:** `document.documentElement.scrollWidth === innerWidth` at every width.
  The only elements reaching past the edge are the decorative marquee track (clipped by
  `overflow:hidden` on purpose) and the visually hidden skip link parked at `left:-9999px`.
- **Section numbering** read back from the live DOM:
  `about=01, services=02, work=03, results=04, process=05, testimonials=06, contact=07`.
- **Contrast guard:** nothing inside the enquiry form renders light text on a light background. The
  heading and hint in the dark contact band resolve to `var(--color-plum)` / `var(--color-muted)`,
  so the white-on-white bug fixed earlier stayed fixed.
- **Class audit:** all 121 classes used in `index.html` resolve to a rule in the compiled CSS except
  `case__content` and `hero__copy`, which are bare layout wrappers with no styling needed — the same
  as before. All 6 classes the JavaScript toggles at runtime (`is-visible`, `is-scrolled`, `is-open`,
  `is-active`, `has-error`, `nav-open`) have rules.
- **Build is clean:** `npm run build` exits 0, the compiled CSS has balanced braces (407/407), and
  `node --check assets/js/main.js` passes.
- **Shipping weight:** `index.html` 12.4 KB + `assets/css/site.css` 7.6 KB +
  `assets/js/main.js` 2.7 KB = **22.7 KB gzipped**, in three separately cacheable files. The old
  single file was 95.5 KB raw. The hero photo adds 31.7 KB of its own (JPEG is already compressed, so
  gzip barely shrinks it).
